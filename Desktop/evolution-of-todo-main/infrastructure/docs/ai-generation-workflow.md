# AI Infrastructure Generation Workflow

**Purpose**: Document the AI-only infrastructure generation process for Phase IV Kubernetes deployment

**Last Updated**: 2026-02-06

## Overview

Phase IV follows an AI-only infrastructure model where all Dockerfiles, Kubernetes manifests, and Helm charts are generated by AI tools. Human role is strictly limited to review, validation, and auditing.

## AI Tools

### Docker AI (Gordon) / Claude Code

**Purpose**: Generate production-ready Dockerfiles

**Setup**:
- **Docker AI (Gordon)**: Install via `npm install -g docker-ai` (if available)
- **Claude Code**: Built-in capability, no additional setup required

**Usage**:
```bash
# Using Docker AI (if available)
docker-ai "Generate production Dockerfile for [technology] with [requirements]"

# Using Claude Code (fallback)
# Provide detailed prompt with all requirements
# Claude Code will generate Dockerfile following best practices
```

**Validation**:
1. Build image: `docker build -t <image> -f <dockerfile> .`
2. Run container: `docker run -p <port>:<port> <image>`
3. Test health endpoint
4. Verify non-root user: `docker exec <container> whoami`
5. Security scan: `docker scan <image>` (if available)

---

### kubectl-ai

**Purpose**: Generate Kubernetes manifests and Helm charts

**Setup**:
- Install: `npm install -g kubectl-ai` (if available)
- Configure: `kubectl-ai config set model gpt-4`

**Alternative**: Claude Code can generate Kubernetes manifests following Kubernetes best practices

**Usage**:
```bash
# Using kubectl-ai (if available)
kubectl-ai "Generate Kubernetes Deployment for [app] with [specs]"

# Using Claude Code (fallback)
# Provide detailed prompt with resource specifications
# Claude Code will generate manifests following Kubernetes conventions
```

**Validation**:
1. Apply manifest: `kubectl apply -f <manifest>`
2. Check status: `kubectl get <resource>`
3. Verify pods: `kubectl get pods -l app=<name>`
4. Check logs: `kubectl logs -l app=<name>`

---

### kagent

**Purpose**: Cluster analysis and diagnostics

**Setup**:
- Install: `npm install -g kagent` (if available)
- Configure: `kagent config set cluster minikube`

**Alternative**: Use standard kubectl commands for cluster analysis

**Usage**:
```bash
# Using kagent (if available)
kagent analyze cluster
kagent diagnose pod <pod-name>

# Using kubectl (fallback)
kubectl get all
kubectl describe pod <pod-name>
kubectl top nodes
kubectl top pods
```

## AI Generation Process

### Step 1: Prepare Prompt

Create detailed prompt with:
- Technology/framework
- Base image requirements
- Port configuration
- Environment variables
- Resource limits
- Health check endpoints
- Security requirements (non-root user, minimal image)

### Step 2: Generate Infrastructure Code

Use AI tool to generate:
- Dockerfiles
- Kubernetes manifests (Deployments, Services, ConfigMaps, Secrets)
- Helm charts (Chart.yaml, values.yaml, templates)

### Step 3: Human Review

Review generated code for:
- Correctness and completeness
- Security best practices
- Resource efficiency
- Alignment with specification

### Step 4: Document Audit Trail

For each generated artifact, document:
- AI tool used
- Exact prompt provided
- Timestamp of generation
- Validation results
- Any manual adjustments (with justification)

### Step 5: Validate

Test generated infrastructure:
- Build and run containers
- Deploy to Kubernetes
- Verify functionality
- Check resource usage

## Prompt Templates

### Dockerfile Generation

**Frontend (Next.js)**:
```
Generate a production-ready Dockerfile for Next.js application with:
- Base image: node:18-alpine
- Multi-stage build (build stage + runtime stage)
- Non-root user for security
- Port 3000 exposed
- Environment variables: NEXT_PUBLIC_API_URL
- Health check endpoint: /api/health
- Optimized for minimal image size
- Security best practices
```

**Backend (FastAPI)**:
```
Generate a production-ready Dockerfile for FastAPI application with:
- Base image: python:3.11-slim
- Multi-stage build (dependencies + runtime)
- Non-root user for security
- Port 8000 exposed
- Environment variables: DATABASE_URL, OPENROUTER_API_KEY, etc.
- Health check endpoint: /health
- Optimized for minimal image size
- Security best practices
```

### Kubernetes Manifest Generation

**Deployment**:
```
Generate Kubernetes Deployment manifest for [app-name] with:
- Image: [image:tag]
- Replicas: [count]
- Container port: [port]
- Environment variables from ConfigMap/Secret
- Resource limits: CPU [limit], Memory [limit]
- Liveness probe: HTTP GET [endpoint], initial delay [seconds]
- Readiness probe: HTTP GET [endpoint], initial delay [seconds]
- Labels: app=[name], tier=[frontend/backend]
- Security context: non-root user
```

**Service**:
```
Generate Kubernetes Service manifest for [app-name] with:
- Type: [ClusterIP/NodePort/LoadBalancer]
- Port: [port]
- Target port: [container-port]
- Selector: app=[name]
- Labels: app=[name]
```

### Helm Chart Generation

```
Generate Helm chart for [app-name] with:
- Chart name: [name]
- Version: [version]
- App version: [app-version]
- Resources: Deployments, Services, ConfigMaps, Secrets
- Configurable values: image tags, replica counts, resource limits, environment variables
- Templates with proper Helm templating syntax
- Default values for local Minikube deployment
```

## Best Practices

### Security
- Always use non-root users in containers
- Use minimal base images (alpine, slim)
- Scan images for vulnerabilities
- Store secrets in Kubernetes Secrets, not ConfigMaps
- Use resource limits to prevent resource exhaustion

### Performance
- Multi-stage builds to reduce image size
- Layer caching optimization
- Appropriate resource requests and limits
- Health checks with proper timing

### Maintainability
- Clear labels and annotations
- Consistent naming conventions
- Comprehensive documentation
- Version all artifacts

### Compliance
- All infrastructure code AI-generated
- Complete audit trails
- Human review documented
- No manual infrastructure coding

## Troubleshooting

### AI Tool Not Available
- **Fallback**: Use Claude Code for all generation
- **Process**: Provide detailed prompts, review output carefully
- **Documentation**: Note fallback used in audit trail

### Generated Code Has Issues
- **Review**: Check prompt for clarity and completeness
- **Refine**: Improve prompt with more specific requirements
- **Regenerate**: Use refined prompt to generate new version
- **Document**: Record iterations in audit trail

### Validation Failures
- **Analyze**: Review error messages and logs
- **Diagnose**: Use kubectl describe, logs, events
- **Fix**: Regenerate with corrected requirements
- **Test**: Validate fix before proceeding
