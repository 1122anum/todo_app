## Summary

Deploy the Phase III Todo Chatbot application to a local Kubernetes cluster (Minikube) using AI-generated infrastructure code. All Dockerfiles will be generated by Docker AI (Gordon) or Claude Code, all Kubernetes manifests will be generated by kubectl-ai/kagent, and all operations will be executed through AI tools. The deployment will support horizontal scaling of the backend and be packaged as a Helm chart for repeatable installation.

**Technical Approach**: AI-only infrastructure generation with human review, local Minikube deployment, zero cloud cost, full audit trail from specification to deployment.

### Design Artifacts

#### D001: Infrastructure Component Model (data-model.md)

Define the infrastructure components and their relationships:

**Components**:
- **Frontend Container**: Next.js application, port 3000, environment variables for backend URL
- **Backend Container**: FastAPI application, port 8000, environment variables for database and OpenRouter
- **Frontend Deployment**: Kubernetes Deployment managing frontend pods, 1 replica
- **Backend Deployment**: Kubernetes Deployment managing backend pods, configurable replicas (1-10)
- **Frontend Service**: LoadBalancer or NodePort exposing frontend to host
- **Backend Service**: ClusterIP exposing backend to frontend only
- **ConfigMap**: Non-sensitive configuration (backend URL, feature flags)
- **Secret**: Sensitive configuration (database credentials, API keys)
- **Helm Chart**: Package containing all resources with configurable values

**Relationships**:
- Frontend Deployment → Frontend Container (uses image)
- Backend Deployment → Backend Container (uses image)
- Frontend Service → Frontend Deployment (routes traffic)
- Backend Service → Backend Deployment (routes traffic)
- Deployments → ConfigMap (mounts configuration)
- Deployments → Secret (mounts secrets)
- Helm Chart → All Resources (templates and manages)

**State Transitions**:
- Container: Building → Built → Pushed → Pulled → Running
- Pod: Pending → Running → Succeeded/Failed
- Deployment: Progressing → Available → Degraded
- Service: Pending → Active

#### D003: Deployment Quickstart (quickstart.md)

```markdown
# Quickstart: Kubernetes Deployment

## Prerequisites
- Minikube installed and running
- Docker installed
- kubectl configured
- Helm 3.x installed
- Docker AI, kubectl-ai, kagent configured

## Quick Deploy (5 minutes)

### Step 1: Start Minikube
\`\`\`bash
minikube start --cpus=2 --memory=4096
\`\`\`

### Step 2: Build Images in Minikube
\`\`\`bash
eval $(minikube docker-env)
docker build -t todo-frontend:latest -f infrastructure/docker/frontend/Dockerfile ./frontend
docker build -t todo-backend:latest -f infrastructure/docker/backend/Dockerfile ./backend
\`\`\`

### Step 3: Install via Helm
\`\`\`bash
helm install todo-chatbot infrastructure/helm/todo-chatbot
\`\`\`

### Step 4: Access Application
\`\`\`bash
minikube service todo-frontend --url
\`\`\`

## Validation
- Check pod status: \`kubectl get pods\`
- Check services: \`kubectl get services\`
- View logs: \`kubectl logs -l app=todo-backend\`
- Test health: \`curl <backend-url>/health\`

## Scaling
\`\`\`bash
kubectl scale deployment todo-backend --replicas=3
\`\`\`

## Cleanup
\`\`\`bash
helm uninstall todo-chatbot
minikube stop
\`\`\`
```

## AI Generation Workflow

### Dockerfile Generation (Docker AI)

**Prompt Template**:
```
Generate a production-ready Dockerfile for [frontend/backend] with:
- Base image: [node:18-alpine / python:3.11-slim]
- Multi-stage build for optimization
- Non-root user for security
- Port [3000/8000] exposed
- Environment variables: [list]
- Health check endpoint: [/api/health or /health]
- Minimal image size
- Security best practices
```

**Validation**:
1. Build image: `docker build -t <image> -f <dockerfile> .`
2. Run container: `docker run -p <port>:<port> <image>`
3. Test health: `curl http://localhost:<port>/health`
4. Check user: `docker exec <container> whoami` (should not be root)
5. Scan security: `docker scan <image>`

### Kubernetes Manifest Generation (kubectl-ai)

**Prompt Template**:
```
Generate Kubernetes manifests for [resource type] with:
- Name: [resource-name]
- Image: [image:tag]
- Replicas: [count]
- Port: [port]
- Environment variables from ConfigMap/Secret
- Resource limits: CPU [limit], Memory [limit]
- Liveness probe: [endpoint], initial delay [seconds]
- Readiness probe: [endpoint], initial delay [seconds]
- Labels: app=[name], tier=[frontend/backend]
```

**Validation**:
1. Apply manifest: `kubectl apply -f <manifest>`
2. Check status: `kubectl get <resource>`
3. Verify pods: `kubectl get pods -l app=<name>`
4. Check logs: `kubectl logs -l app=<name>`
5. Test service: `kubectl port-forward svc/<service> <port>:<port>`

### Helm Chart Generation (kubectl-ai)

**Prompt Template**:
```
Generate Helm chart for todo-chatbot application with:
- Chart name: todo-chatbot
- Version: 1.0.0
- Resources: Deployments (frontend, backend), Services, ConfigMap, Secret
- Configurable values: image tags, replica counts, resource limits
- Templates with proper templating syntax
- Default values for local Minikube deployment
```

**Validation**:
1. Lint chart: `helm lint infrastructure/helm/todo-chatbot`
2. Dry run: `helm install --dry-run --debug todo-chatbot infrastructure/helm/todo-chatbot`
3. Install: `helm install todo-chatbot infrastructure/helm/todo-chatbot`
4. Check status: `helm status todo-chatbot`
5. Test overrides: `helm upgrade todo-chatbot infrastructure/helm/todo-chatbot --set backend.replicas=3`
6. Uninstall: `helm uninstall todo-chatbot`

## Risk Mitigation

### Technical Risks

**Risk**: AI-generated Dockerfiles contain security vulnerabilities
- **Mitigation**: Human review of all generated Dockerfiles, security scanning, non-root user enforcement
- **Validation**: Docker scan, manual security checklist review

**Risk**: Kubernetes manifests have incorrect resource limits causing OOM kills
- **Mitigation**: Conservative resource limits based on Phase III testing, monitoring pod restarts
- **Validation**: Load testing, resource usage monitoring

**Risk**: Minikube resource constraints on developer machines
- **Mitigation**: Document minimum requirements, provide resource limit configurations
- **Validation**: Test on minimum spec machine

**Risk**: Container networking issues preventing frontend-backend communication
- **Mitigation**: Use Kubernetes DNS for service discovery, test networking thoroughly
- **Validation**: Integration tests, service connectivity checks

- **Validation**: Test all AI tools before starting implementation

**Risk**: Generated infrastructure code requires significant manual fixes
